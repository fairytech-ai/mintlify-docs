title: "Confirmed earnings list API"
---

If you want to convert monthly confirmed cashback earnings into your own rewards (custom currency, coupons, etc.), use Fairy's **confirmed-earnings API** to pull the data and drive your reward conversion logic.

A typical implementation: **at monthly settlement time (around the 5th–7th), run a batch job or scheduled task that calls the API**, pulls the confirmed earnings for the month, and executes the conversion logic.

# Confirmed earnings API spec

## Request

### Endpoint

```http
GET /organization/{ORGANIZATION_PUBLIC_ID}/settled_transactions
```

Base URL: `https://api.public.moment.fairytech.ai`

### Headers

| Header | Required | Description |
| :-- | :-- | :-- |
| x-moment-api-key | O | Server API Key issued by Fairy |

### Path parameters

| Parameter | Type | Description | Required | Default |
| :-- | :-- | :-- | :-- | :-- |
| organizationPublicId | string | Host ID | O | - |

Replace `{ORGANIZATION_PUBLIC_ID}` with the customer ID provided by Fairy.

<Tip>
  If you haven't received `{ORGANIZATION_PUBLIC_ID}`, contact [eng@fairytech.ai](mailto:eng@fairytech.ai).
</Tip>

### Query string

| Parameter | Type | Description | Required | Default |
| :-- | :-- | :-- | :-- | :-- |
| year | number | Year to query (YYYY) | O | - |
| month | number | Month to query (1-12) | O | - |
| page | number | Page number | X | 1 |
| limit | number | Rows per page (1–100) | X | 100 |
| user\_id | string | Single user ID to query | X | - |

If you pass `user_id`, only that user's earnings are returned; in that case the response is by single user, so page and limit are unnecessary.

### Request example

```bash
ORGANIZATION_PUBLIC_ID="{ORGANIZATION_PUBLIC_ID}"
SERVER_API_KEY="{SERVER_API_KEY}"
YEAR="2025"
MONTH="11"
PAGE="1"
LIMIT="20"

curl -X GET \
  "https://api.public.moment.fairytech.ai/organization/${ORGANIZATION_PUBLIC_ID}/settled_transactions?year=${YEAR}&month=${MONTH}&page=${PAGE}&limit=${LIMIT}" \
  -H "x-moment-api-key: ${SERVER_API_KEY}"
```

## Response

### Data

| Field | Type | Description |
| :-- | :-- | :-- |
| totalCount | number | Total row count |
| totalPage | number | Total page count |
| currentPage | number | Current page number |
| settlementItems | `settlementItem`\[\] | Transaction rows |

- `settlementItem`
  | Field | Type | Description |
  | :-- | :-- | :-- |
  | userId | string | User ID |
  | confirmedAmount | number | Sum of the user's confirmed-earnings commission |
  - We return commission summed per user (deduplicated) across every transaction in the query range, sorted ascending by userId.
  - `confirmedAmount` is the sum of each of the user's individual commissions rounded up.

### Response example

```json
{
  "totalCount": 40,
  "totalPage": 20,
  "currentPage": 1,
  "settlementItems": [
    {
      "userId": "USER-123",
      "confirmedAmount": 957
    },
    {
      "userId": "USER-456",
      "confirmedAmount": 4877
    },
  ]
}
```
